# References, provenance and public-repository safety

The repository is intentionally public for now. This file is a handling policy, not a legal determination about ownership or redistribution rights. Visibility and permissions remain unchanged unless the owner explicitly authorizes a change.

## Keep three roles distinct

Northstar images define visual language. Project plans define scope, geometry/relationships and revision evidence. Finished photographs explain physical composition. None is interchangeable with an executable fixture or actual app output. [references/manifest.json](references/manifest.json) records stable aliases, the five previously recorded visual filename locators, availability and publication status without private client identifiers.

The image filenames are retrieval hints from the earlier repo specification, not accessible downloads or proof that a fresh chat can see their pixels. Original client documents/photos and the visual images are not being uploaded in this consolidation. Do not invent hashes, paths, approvals or access.

## Public material

Publish requirements, generalized scenario descriptions, original synthetic geometry, original code/assets, and reviewed non-identifying evidence. For any external image or derivative, establish provenance and permission separately from redaction. Construction drawings are not made safe to publish merely by covering a title block; lot geometry, source names, contact details and embedded metadata can still identify a project.

Do not commit originals, client/company source files, identifying screenshots, contracts, pricing records, private storage links, device/account identifiers, access tokens, local user paths or extracted source text. Apply this to commit messages, issue/PR text, Actions logs/caches/artifacts, release attachments and Git LFS as well as the working tree. A private label or ignored folder is not an access-control system, and deleting a committed file does not erase history.

Prefer storing private originals outside the checkout. Optional local-only folders such as `.private/` and `private-references/` are ignored as an extra guard, not a permission to place their contents in public builds. Avoid broad staging commands when reference files are nearby. Inspect the staged diff, filenames and binaries explicitly before publication.

## Reference intake and recovery

Keep the client-to-alias mapping in owner-controlled private storage, not this repo. Record source revision/status and checksums privately when source bytes are available. A small private index accompanying this session can map the public case IDs back to the supplied files; it is not an automatically configured private repository or a guaranteed backup.

For a future visual task, retrieve the listed Northstar originals through the owner's available private files or request them. If unavailable, continue appropriate nonvisual work using the contract, but do not claim visual parity or silently substitute different art. The absence of project originals does not block synthetic fixtures. An approved public reference can later be added with a relative path, provenance, license/permission and verified checksum.

No private hosting service, repository visibility switch or account integration is created by these documents. Maintain the portable separation between public code/specifications and privately held reference material.
