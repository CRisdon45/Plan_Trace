# Plan Trace

**A personal, pen-first pool and landscape design workspace for working out complete projects with a client.** Tracing is one way to start, not the product's identity.

The goal is to keep up with an experienced designer: create the site, compose the whole yard, revise connected objects, show an attractive plan throughout the meeting, and preserve an editable, measurable result. This is in development, not a claim of finished capabilities.

## Start here in a new session

Read [AGENTS.md](AGENTS.md), [current state and next outcome](docs/CURRENT_STATE.md), and [product direction](docs/PRODUCT_VISION.md). Then open only the contracts/evidence relevant to the task. The repository, not an unavailable conversation, carries the working context.

**Use [CURRENT_STATE.md](docs/CURRENT_STATE.md) to find the active implementation branch, stacked pull requests and tested application revision.** The default main branch carries the context/routing package without necessarily containing unfinished application code. Verify live refs before making changes; do not choose a work branch from an old report or assume the tablet build matches the latest code. Old perspective/Filament branches are not the current roadmap.

## Boundaries

No runtime AI. Local-first, deterministic behavior. 3D paused. Preserve original app/project data. No company/client originals or unapproved reference art in this public repository, its discussions or build artifacts. [AGENTS.md](AGENTS.md) explains the small maintenance loop that keeps these documents useful without making every future session reread the entire history.
